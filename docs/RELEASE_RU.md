# Выпуск офлайн-версии

Публикацию ведёт Codex / dot по поручению владельца. Изменения попадают в main через PR; предыдущие релизы сохраняются.

1. Зафиксировать исходный коммит. В его checkout выполнить `python3 scripts/build-offline.py`.
2. Проверить работу самостоятельного HTML и записать напечатанный SHA256. Сборщик ограничивает файл 40 000 000 байт (потолок площадки — 50 МБ); `terra.html` в Git не добавлять.
3. Создать черновик GitHub Release с заметками и новым тегом. Не назначать пустой черновик последним публичным выпуском.
4. В Actions запустить **Publish verified offline release**: указать полный SHA коммита, тег черновика и ожидаемый SHA256 файла.
5. Дождаться успешного workflow и проверить два вложения: `terra.html` и `SHA256SUMS.txt`, размер, SHA и соответствие тега исходному коммиту.

Workflow использует штатный GITHUB_TOKEN с правом contents:write. Личные токены и секреты для него не требуются. Он отказывается заменять опубликованный релиз или использовать уже существующий тег другого коммита. Файл публикуется только после совпадения контрольной суммы.

Браузерный сайт публикует штатный GitHub Pages из main. Состояние Pages проверяется отдельно от офлайн-выпуска. Новые функции не следует объявлять опубликованными только по факту локальной сборки.
